# AI Provider Migration Checklist

Use this when testing a new provider or when a subscription is ending.

## Context portability
- Provider can read `/AGENTS.md` and `/munin-context/`.
- Provider understands local-first, zero-mandatory-cost, safety, and BUILD ALL constraints.
- No private chat export is required for normal project continuation.

## A/B benchmark
Run the same brief on incumbent and candidate provider. Suggested benchmark set:
1. Fresh job-market scan for high-fit financial technology/product roles, including digital assets/stablecoins where relevant.
2. Deep dive on five current GitHub projects and concrete Munin integration recommendations.
3. Research-backed professional content brief with source quality assessment.
4. Repository continuation task: recover current architecture and propose the smallest safe implementation.

Score each 1–5 on evidence quality, factual accuracy, project-context recovery, actionability, intervention required, latency, cost, and ability to execute rather than merely advise.

## Decision rule
Do not retain a paid provider solely because historical context is trapped there. Fix context portability first. Keep a paid provider only when its incremental capability/value justifies the recurring cost after A/B testing.

## Security
Do not migrate secrets, OAuth tokens, credentials, private raw communications, or unnecessary personal data into a provider context file. Use authorized connectors and Munin's private/durable state mechanisms instead.
