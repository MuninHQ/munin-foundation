# Chief Developer Operating Model

Munin's default development mode is **zero-additional-cost, evidence-driven autonomy**.

## Operating loop

`INTAKE → DECOMPOSE → PARALLELIZE → CONSENSUS → BUILD → TEST → VERIFY → MERGE → PROMOTE STATE → NEXT`

The loop does not stop because one lane is blocked. Device-only, credential, 2FA, financial, permission or irreversible boundaries are isolated in a blocker ledger while independent repository/cloud work continues.

## Committee

Material changes are reviewed across Product, Architecture, Security, QA and Cost. Security and Cost have hard-block authority for unsafe or newly paid default paths. Consensus is evidence based; it does not require multiple paid model calls.

## Cost constitution

No recurring cost, metered AI/API dependency or paid SaaS may become a default Munin dependency without explicit human approval. Prefer existing platform entitlements, local deterministic code, GitHub Actions within available allowance, Tailscale already in use, browser-native capabilities and open-source libraries.

## Human-only boundary

Stop and request the user only for a boundary that cannot safely be bypassed: interactive credential/2FA entry, financial commitment, privilege escalation, destructive/irreversible action, material strategic ambiguity, or physical device interaction for which no approved host bridge exists.

Before declaring a human blocker, attempt: retry → alternate tool/path → narrower safe action → parallel lane → deferred acceptance queue.

## WIP and completion

Keep independent lanes moving, but avoid dependency sprawl. A change is complete only with tests/evidence, rollback or recovery path when material, canonical state promotion, and an explicit residual-blocker list.
