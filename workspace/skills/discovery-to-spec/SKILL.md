# Discovery to Spec

1. Restate the user outcome and non-goals.
2. Inspect repository and durable project context.
3. Identify assumptions, constraints, risks, dependencies, and open questions.
4. Prefer existing capabilities over new architecture.
5. Produce acceptance criteria and a testable definition of done.
6. Separate product decisions requiring approval from implementation details.
7. Do not edit code until the specification is internally consistent.

Output: context, problem, goal, non-goals, scope, constraints, proposed approach, acceptance criteria, risks, questions, and next action.
