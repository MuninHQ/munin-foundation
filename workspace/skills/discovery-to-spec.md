# Skill: Discovery to Spec

Use when a request is ambiguous, strategic, or likely to create multiple files.

## Procedure

1. State the user problem and desired outcome.
2. Inspect existing repository context and decisions.
3. Separate known facts from assumptions.
4. Define scope, non-goals, constraints, and risks.
5. Write measurable acceptance criteria.
6. Break work into independently verifiable tasks.
7. Obtain approval only for decisions that are irreversible, costly, security-sensitive, or outside granted authority.

## Completion gate

A specification is ready only when an executor can identify what to change, what not to change, and how completion will be verified.
